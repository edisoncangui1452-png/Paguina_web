01 · CONCEPTO

¿Qué es la arquitectura monolítica?

Una aplicación monolítica se construye y se ejecuta como una sola unidad, aunque por dentro tenga varios módulos.

◈

Un solo sistema, varias responsabilidades

En una arquitectura monolítica, la interfaz, las reglas del negocio y el acceso a los datos suelen vivir en la misma aplicación. Sus módulos pueden estar separados en el código, pero se compilan, publican y escalan juntos.

Esto no significa que el código deba ser desordenado: una estructura modular ayuda a entender y mantener el sistema.

EJEMPLO COTIDIANO

Como una casa con varias habitaciones

La cocina, el dormitorio y la sala tienen funciones distintas, pero forman parte de la misma casa. Si se cambia de vivienda, se traslada el conjunto.

02 · ESTRUCTURA

Características principales

Estas propiedades describen cómo se organiza y entrega una aplicación monolítica.

▦

Aplicación integrada

Las funciones principales conviven dentro de una aplicación coordinada.

⬆

Despliegue unificado

Los cambios se publican como una nueva versión del sistema completo.

⌘

Módulos relacionados

Los módulos colaboran mediante llamadas internas y comparten el mismo contexto.

✦

Inicio sencillo

Un solo proyecto y despliegue facilitan comenzar con un producto pequeño.

03 · BALANCE

Ventajas y desventajas

La mejor elección depende del tamaño del producto, del equipo y de sus necesidades.

+

Ventajas

  • ✓
    Desarrollo inicial directo

    Un proyecto central puede reducir la configuración necesaria para empezar.

  • ✓
    Depuración más sencilla

    Es posible seguir el flujo de ejecución dentro de una misma aplicación.

  • ✓
    Comunicación interna rápida

    Los módulos pueden comunicarse sin llamadas de red entre servicios.

  • ✓
    Operación inicial simple

    Un artefacto y un proceso de despliegue pueden bastar al comienzo.

−

Desventajas

  • !
    Despliegue de todo el sistema

    Una modificación puede requerir publicar de nuevo la aplicación completa.

  • !
    Escalado menos selectivo

    Se suele escalar la aplicación entera, aunque solo una parte necesite más recursos.

  • !
    Acoplamiento al crecer

    Las dependencias entre módulos pueden volver más difícil cambiar el sistema.

  • !
    Mayor impacto de fallos

    Un problema grave en el proceso puede afectar a varias funcionalidades.

05 · OTRAS ARQUITECTURAS

Monolito frente a microservicios

Los microservicios separan el sistema en servicios pequeños que pueden desplegarse de forma independiente.

Aspecto Monolito Microservicios
OrganizaciónUna aplicación con módulos internos.Varios servicios independientes.
DespliegueLa aplicación se publica como una unidad.Cada servicio puede publicarse por separado.
EscalabilidadSe escala habitualmente el sistema completo.Se pueden escalar servicios específicos.
ComplejidadMenos complejidad operativa al comenzar.Más infraestructura y coordinación distribuida.
MantenimientoPuede ser sencillo al inicio; los módulos acoplados lo dificultan al crecer.Se mantiene cada servicio, aunque hay más componentes.
ComunicaciónLlamadas internas dentro del proceso.Comunicación entre servicios, a menudo por red.

✦ Ninguna arquitectura es siempre mejor: elige según las necesidades reales del proyecto.
